Agile

StudentEats is my team’s Agile project. Everything here is part of how we plan, build and review it.

1. Agile team charter

A charter is a living team agreement. Review it with the actual team and update it as requirements change.

Charter areaAgreement
PurposeHelp CPUT-area student sellers present meals and help student buyers discover convenient food options.
UsersStudent food sellers and student buyers near CPUT residences and campus.
ValuesRespect, transparency, inclusion, collaboration, and honest progress reporting.
Working agreementsHold short check-ins; update the task board; ask for help early; review work before marking Done.
Definition of DoneAcceptance criteria met; layout reviewed at target screen sizes; no known blocking errors; evidence recorded.
Current boundaryFocus on frontend layout unless backend, payments, accounts, or live ordering are explicitly included.
RisksUnclear seller rules, trust/food-safety concerns, incomplete content, and scope growth.
Roles (confirm)Product/requirements lead: [name]; facilitator: [name]; designers/developers: [names].

2. User stories and tasks

Stories describe a user goal; tasks describe the work required. Priorities are suggestions and should be confirmed.

StudentEats

IDPriorityUser storyAcceptance criteriaTasks
SE-01MustAs a buyer, I want to view meals so I can discover food options near campus.Meal cards show the available approved details and do not break when information is missing.Create meal card; add sample data; style cards; test long names and missing images.
SE-02MustAs a seller, I want my food offer presented clearly so buyers understand what I sell.Meal/seller information is consistently displayed.Define fields; create card layout; add empty state; test layout.
SE-03ShouldAs a buyer, I want to filter meals so I can find options faster.If filtering is in scope, selecting a filter updates results and can be cleared.Confirm requirements; build controls; implement sample-data filtering; test reset.
SE-04MustAs a user, I want clear navigation so I can move between main sections.Navigation links work and labels are understandable.Build navigation; connect links/routes; test keyboard and mobile navigation.
SE-05ShouldAs a mobile user, I want the site to fit my screen so I can browse on campus.Key content is not clipped at common mobile widths.Add breakpoints; test narrow screens; fix overflow; record screenshots.
